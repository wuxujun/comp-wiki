# 项目式学习与问题式学习

Project-Based Learning 与 Problem-Based Learning 都常被缩写为 PBL，也都以真实或复杂问题、学生主动探究、小组协作和教师促进为重要特征，但两者的组织中心不同。为避免研究、课程和产品资料互相污染，本知识库将前者写作 PjBL，将后者写作 PrBL；单独出现 PBL 时必须根据来源重新判断。

## 核心对比

| 维度 | Project-Based Learning（PjBL） | Problem-Based Learning（PrBL） |
|---|---|---|
| 组织中心 | 持续项目及其成果 | 驱动学习的复杂或结构不良问题 |
| 常见输出 | 作品、产品、设计、报告、展览或公开展示 | 问题解释、诊断、方案、决策或论证 |
| 时间结构 | 通常跨多个阶段，包含计划、制作、反馈和修订 | 常从问题情境进入自我导向学习，再回到问题整合方案 |
| 成果地位 | 可见成果通常是方法的必要组成部分 | 解决方案重要，但不必形成公开产品或完整作品 |
| 知识关系 | 在制作和修订成果的过程中建构、应用知识 | 为理解和解决问题识别知识缺口，再研究与整合 |
| 典型风险 | 作品制作压过学科理解 | 讨论问题但知识搜集、整合或指导不足 |

Savery 将 PrBL 定义为以学习者为中心、围绕问题开展研究、整合理论与实践并形成可行解决方案的方法；参见[Savery 2006 年问题式学习定义来源](../sources/external-savery-2006-problem-based-learning.md)。PjBL 的综述则强调产生作品是关键特征，并指出作品本身在现有评价中反而常被忽略；参见[Guo 等 2020 年高等教育 PBL 综述来源](../sources/external-guo-2020-higher-education-pbl-review.md)。

## 重叠与混合

两种方法不是互斥分类。一个 PjBL 项目可以由结构不良问题启动，也可以在项目中使用 PrBL 周期；反过来，PrBL 也可能要求用报告、模型或演示表达解决方案。真正需要区分的是问题、探究、产品和评价各自承担什么功能，而不是课程自称哪个标签。

## 为什么术语会影响证据

2026 年伞式综述指出，两种方法共用 PBL 缩写并常被混合编码，导致元分析样本受到概念污染。若研究实际包含不同干预，合并后的效果量就难以解释，也不能直接用于预测某个具体项目；参见[Farshad 与 Fortin 2026 年 PBL 伞式综述来源](../sources/external-farshad-fortin-2026-pbl-umbrella-review.md)。

## 使用规则

- 英文首次出现时写全称，并使用 `PjBL` 或 `PrBL`。
- 来源只写 `PBL` 时，检查是否有持续项目、可见产品、问题驱动和自我导向学习等描述。
- 无法确定时保留原文术语，并标注“定义不清”，不要替来源重新分类。
- 比较研究时检查纳入标准，不因标题含 `PBL` 就认为研究对象相同。
